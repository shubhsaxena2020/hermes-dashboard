### Step 1: Create `web/src/lib/container-utils.ts`

Extract these 3 functions + the constant from `ContainerTable.tsx` lines 38–65,
character-for-character. Only add the export keyword and the necessary types.

```typescript
// Docker's `stats --format` output, e.g. "27.19%" and "3.42GiB / 7.75GiB" --
// parsed client-side purely to flag containers worth a second look.
export function parseCpuPercent(cpu?: string): number | null {
  if (!cpu) return null
  const n = parseFloat(cpu)
  return Number.isNaN(n) ? null : n
}

export const MEM_UNIT_BYTES: Record<string, number> = {
  B: 1,
  KiB: 1024,
  MiB: 1024 ** 2,
  GiB: 1024 ** 3,
  TiB: 1024 ** 4,
}

export function parseMemBytes(part: string): number | null {
  const m = part.trim().match(/^([\d.]+)\s*(B|KiB|MiB|GiB|TiB)$/)
  if (!m) return null
  return parseFloat(m[1]) * MEM_UNIT_BYTES[m[2]]
}

// mem is "<used> / <total-host-memory>" -- there's no per-container limit set
// on these containers, so this is really "% of host RAM," which is still a
// useful signal for "this one container is eating the box."
export function parseMemPercent(mem?: string): number | null {
  if (!mem) return null
  const [usedStr, totalStr] = mem.split('/')
  if (!usedStr || !totalStr) return null
  const used = parseMemBytes(usedStr)
  const total = parseMemBytes(totalStr)
  if (used == null || !total) return null
  return (used / total) * 100
}
```

### Step 4: Add test config to `web/vite.config.ts`

**Do NOT create `vitest.config.ts`**. vitest 4 resolves config files in order:
`vitest.config.ts` first, then `vite.config.ts`. Creating a separate
`vitest.config.ts` without the `@` alias would break all 32 existing tests
that import via `@/lib/...`.

Instead, add a `test` block to the existing `vite.config.ts`:

```typescript
import path from 'node:path'
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import tailwindcss from '@tailwindcss/vite'

export default defineConfig({
  plugins: [react(), tailwindcss()],
  resolve: {
    alias: {
      '@': path.resolve(__dirname, './src'),
    },
  },
  server: {
    proxy: {
      '/api': 'http://localhost:4000',
    },
  },
  test: {
    coverage: {
      provider: 'v8',
      include: ['src/lib/**/*.ts'],
      reporter: ['text', 'text-summary'],
    },
  },
})
```

## Risk notes

1. **vitest config split (MITIGATED)**: The devil's advocate correctly identified
   that creating `vitest.config.ts` would break all 32 existing tests by
   overriding `vite.config.ts` (which has the `@` alias). We avoid this entirely
   by adding the `test` block to `vite.config.ts` — Option B from the review.

2. **Unused import (MITIGATED)**: `parseMemBytes` is only called internally by
   `parseMemPercent` inside `container-utils.ts`, never directly by
   `ContainerTable.tsx`. The import in the component must be only
   `parseCpuPercent` and `parseMemPercent`. With `noUnusedLocals: true`, the
   unused import would fail `tsc -b`.

3. **Coverage dep version drift (LOW)**: `@vitest/coverage-v8` must match the
   installed vitest version. Pinning to `^4.1.10` matches the current vitest
   `4.1.10`.

4. **No runtime risk**: All new files are pure utility functions and dev-only
   test/config. The production bundle and server are unchanged.
